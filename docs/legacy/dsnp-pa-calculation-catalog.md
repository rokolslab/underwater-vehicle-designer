# Каталог расчётов ДСНП_ПА

## Назначение и границы

Документ фиксирует формулы, которые удалось непосредственно прочитать в исходниках ДСНП_ПА 1996 года. Исходники рассматриваются как исторический reference: наличие выражения в Pascal-коде подтверждает только поведение программы, но не инженерную корректность метода.

Исходный каталог: `/home/oitroot/dev/dsnp-pa-legacy/source-original/dip_15/`. Файлы прочитаны как CP866 без изменения оригиналов. Нумерация строк ниже относится к распакованным оригиналам. Внешние стандарты, учебники, отчёт дипломного проекта и экспериментальные данные в анализ не входили.

## Шкала достоверности

| Уровень | Значение |
| --- | --- |
| **A** | Стандартная физическая или математическая формула; это не подтверждает корректность входных данных и области применения. |
| **B** | Формула полностью читается из кода, но методический источник неизвестен. |
| **C** | Эмпирическая зависимость или коэффициенты без подтверждённого источника. |
| **D** | Поведение восстановлено только частично. |
| **E** | Недостаточно данных. |

`Статус проверки` в каталоге сочетает уровень A–E и фактический объём проверки. Ни одна запись не прошла независимую инженерную валидацию.

## 1. `UDIFFER.PAS`: удифферентовка и инерция

Источник типов: `TYPE_PA.PAS`, records `Differ_a` и `Differ` (строки 247–297). Расчёт обходит ровно 30 элементов (`UDIFFER.PAS`, `Raschet_Udiffer`, строки 37–110).

### 1.1. Суммарные масса, объём и центры

| Поле | Описание |
| --- | --- |
| **Название** | Суммарные масса/объём, центр тяжести (ЦТ) и центр объёма (исторически обозначен `Xc,Yc,Zc`) |
| **Pascal-файл** | `UDIFFER.PAS` |
| **Процедура или функция** | `Raschet_Udiffer` (строки 17–58) |
| **Входные данные** | Для 30 статей: `Massa`, `Obem`, координаты `X,Y,Z`, локальные смещения ЦТ `Xg,Yg,Zg` |
| **Выходные данные** | `Sum_m`, `Sum_V`, `Xg,Yg,Zg`, `Xc,Yc,Zc`, промежуточные моменты `Xm…ZV` |
| **Формула** | `Σm=Σmᵢ`; `ΣV=ΣVᵢ`; `G=(Σ mᵢ·(rᵢ+gᵢ))/Σm`; `C=(Σ Vᵢ·rᵢ)/ΣV` |
| **Единицы измерения** | UI указывает кг, л, м, кг·м и л·м (`TabUdif`, строки 157–203). Для центра — м. |
| **Константы и коэффициенты** | 30 фиксированных статей; коэффициентов нет. |
| **Граничные условия** | При `Σm=0` компоненты ЦТ равны 0; при `ΣV=0` компоненты центра объёма равны 0. Отрицательные массы/объёмы не запрещены. |
| **Современный аналог** | Pure reducer в `balance`: взвешенные центры для типизированных mass и displaced-volume contributions. Исторический `C` нельзя автоматически объявлять ЦВ внешнего корпуса. |
| **Статус проверки** | **A (математика), B (семантика данных)** — формулы взвешенного среднего читаются полностью; физический смысл `Obem` и локальных смещений требует подтверждения. |
| **Риск переноса** | **Высокий**: исторические оси и начало координат не документированы в процедуре; необходим явный adapter в Body/SNAME-NED. |

### 1.2. Высота между центрами и оценки углов

| Поле | Описание |
| --- | --- |
| **Название** | `h`, `Psi`, `Teta` — диагностические показатели взаимного положения ЦТ и центра объёма |
| **Pascal-файл** | `UDIFFER.PAS` |
| **Процедура или функция** | `Raschet_Udiffer` (строки 56–58) |
| **Входные данные** | `Xg,Yg,Zg`, `Xc,Yc,Zc` |
| **Выходные данные** | `h`, `Psi`, `Teta` |
| **Формула** | `h=Zc−Zg`; `Psi=(Xg−Xc)/h·180/π`; `Teta=(Yg−Yc)/h·180/π` |
| **Единицы измерения** | `h` — м; `Psi`, `Teta` выводятся как градусы по множителю `180/π`. |
| **Константы и коэффициенты** | `180/π` |
| **Граничные условия** | При `h=0` углы остаются нулевыми после предварительной инициализации. Нет `atan`/`atan2`, проверки малости `h` или нормализации угла. |
| **Современный аналог** | Диагностические углы ориентации в `balance/stability`, вычисляемые через `atan2(Δгоризонталь, Δвертикаль)` и с явной системой осей. |
| **Статус проверки** | **B как точное воспроизведение кода; инженерно не проверено.** Линейное отношение равно малоугловому приближению в радианах, но код не ограничивает малые углы. |
| **Риск переноса** | **Критический**: имена `Psi/Teta`, направления осей и знаки могут не соответствовать современным крену/дифференту; буквальное копирование недопустимо. |

### 1.3. Собственные моменты инерции тел

| Поле | Описание |
| --- | --- |
| **Название** | Диагональные собственные моменты инерции элемента |
| **Pascal-файл** | `UDIFFER.PAS` |
| **Процедура или функция** | `Raschet_Udiffer` (строки 59–94) |
| **Входные данные** | `Forma`, `Massa`, размеры `L,B,H`; существующие `I_sx,I_sy,I_sz` |
| **Выходные данные** | `I_sx,I_sy,I_sz` |
| **Формула** | Сфера: `I=2/5·m·(H/2)²`. Цилиндр: вокруг оси `1/2·m·r²`, поперёк `1/12·m·(3r²+L²)`; выбор оси сделан сравнением равных размеров. Иначе параллелепипед: `Ix=m(H²+B²)/12`, `Iy=m(H²+L²)/12`, `Iz=m(L²+B²)/12`. |
| **Единицы измерения** | кг·м² |
| **Константы и коэффициенты** | `2/5`, `1/2`, `1/12`, `3`; радиус в ветвях сферы/цилиндра задан через `H/2`. |
| **Граничные условия** | Автовычисление выполняется только если `I_sx=0`; ненулевой `I_sx` блокирует пересчёт всех трёх компонент. Ось цилиндра определяется точными сравнениями `B=H`, `L=H`, `B=L`; несколько ветвей могут выполниться последовательно. Произведения инерции отсутствуют. |
| **Современный аналог** | Отдельные pure-функции тензора инерции сферы, цилиндра и box с явной orientation и полной матрицей 3×3. |
| **Статус проверки** | **A для идеализированных тел; D для выбора оси и shape mapping.** |
| **Риск переноса** | **Высокий**: точное равенство размеров, неоднозначный радиус и отсутствие ориентации могут дать неверную ось. |

### 1.4. Перенос и суммирование моментов инерции

| Поле | Описание |
| --- | --- |
| **Название** | Теорема параллельных осей и суммарные диагональные моменты ПА |
| **Pascal-файл** | `UDIFFER.PAS` |
| **Процедура или функция** | `Raschet_Udiffer` (строки 96–109) |
| **Входные данные** | `mᵢ`, собственные `I_si`, координата элемента `X,Y,Z`, общий ЦТ `Xg,Yg,Zg` |
| **Выходные данные** | `Ix_p,Iy_p,Iz_p`, `Ix,Iy,Iz`, `I_PA_x,I_PA_y,I_PA_z` |
| **Формула** | `Ix=I_sx+m[(Y−Yg)²+(Z−Zg)²]`; аналогично `Iy`, `Iz`; затем суммирование по элементам. |
| **Единицы измерения** | кг·м² |
| **Константы и коэффициенты** | Нет. |
| **Граничные условия** | Все 30 записей участвуют независимо от `Razm`; продукты инерции и поворот локального тензора отсутствуют. При расчёте общего ЦТ использовались `X+Xg`, но при переносе — только `X`, что требует проверки смысла локальных `Xg`. |
| **Современный аналог** | Суммирование полных тензоров после rotation и parallel-axis shift к общему ЦТ. |
| **Статус проверки** | **A для диагональной части теоремы; D для согласованности координат и неполного тензора.** |
| **Риск переноса** | **Высокий**: историческая реализация не даёт суммарный тензор и потенциально использует разные центры в двух шагах. |

## 2. `HODK.PAS`: ходкость и энергетика

Вся цепочка находится в `Rasch_Hodk` (строки 18–152), а её переменные — в `TYPE_PA.PAS`, record `Hodok` (строки 19–97). Ни один численный коэффициент не имеет ссылки на методику в исходнике.

### 2.1. Геометрия, число Рейнольдса и коэффициент трения

| Поле | Описание |
| --- | --- |
| **Название** | Мидель, число Рейнольдса и `Tpl` |
| **Pascal-файл** | `HODK.PAS` |
| **Процедура или функция** | `Rasch_Hodk` (строки 24–54) |
| **Входные данные** | `L,B,H,Kr,Priam,Vs,OmegaLK,Lcw`, `Delta` |
| **Выходные данные** | `Midel,Re,Tpl,Kf,Kr,Kudl,Kcv,Tfrm,Tg` |
| **Формула** | `Re=L·(Vs·0.5144)/(1.56·10⁻⁶)`; `Tpl=0.075/(log10(Re)−2)²`; эллиптический мидель `πBH/4`; далее `Kf=1.636−0.123L/(B+H)+0.02·max(H/B,B/H)`, `Kcv=1+0.31Lcv` и др. |
| **Единицы измерения** | `L,B,H` — м; `Vs` предположительно узлы (множитель 0.5144); `Re` и коэффициенты безразмерны; `Midel` — м². |
| **Константы и коэффициенты** | `0.5144`, `1.56·10⁻⁶`, `0.075`, `2`, `1.636`, `0.0615`, `0.02`, `0.31`, `0.09`, `0.6`; нижние clamps `Kf≥1`, `Kr≥1`. |
| **Граничные условия** | Нет явной проверки `Re>0` перед `ln`; проверяется лишь `Re<>0`. Для `Lcv=1` выражение `Lkz=0` попадает под корень/деление. В прямоугольной ветви возможны неоднозначные размеры. |
| **Современный аналог** | Отдельный validated resistance-input и pure-функции Reynolds/friction/form factors с единицами SI. |
| **Статус проверки** | **A** только для определения `Re` и узнаваемой формы линии трения; **C** для поправочных коэффициентов и их композиции. |
| **Риск переноса** | **Критический** без методического источника, диапазонов и эталонных примеров. |

### 2.2. Добавочное сопротивление и полное сопротивление

| Поле | Описание |
| --- | --- |
| **Название** | Влияние углублений, отверстий, выступающих частей и рулей |
| **Pascal-файл** | `HODK.PAS` |
| **Процедура или функция** | `Rasch_Hodk` (строки 56–103) |
| **Входные данные** | До 6 `Uglubl` и 6 `Soobsh`, площади, координаты, `Skvr,Skgr,Sgst,Svst`, размеры рулей, `Tg`, плотность воды, скорость |
| **Выходные данные** | `NbIo,NbSo,NbSt,Tlk,To_r,NbOr,Tpa,R_gk,R_lk` |
| **Формула** | Коэффициенты суммируются в `Tpa=Tg+NbIo+NbSo+NbSt+NbOr`; сопротивление `R=T·ρ·1000·(Vs·0.5144)²/2·OmegaGK`. Части `Nb*` содержат эмпирические зависимости, включая `(1−0.085(x/L)^0.885)²`. |
| **Единицы измерения** | Площади — м²; `ρ` в UI/record предположительно кг/л, поэтому `×1000`; `R` — Н. |
| **Константы и коэффициенты** | `0.033`, `0.042`, `1.15`, `0.0102`, `0.00093`, `0.085`, `0.885`; default-площади `0.08/0.10/0.12/0.15·LBHDelta`. |
| **Граничные условия** | Проверки знаменателей фрагментарны; `Otnosh` сообщающегося отверстия не сбрасывается при `OmegaGK=0`; отрицательные/нефизические результаты не запрещены. |
| **Современный аналог** | Составная модель resistance breakdown с отдельными contributions и provenance каждого коэффициента. |
| **Статус проверки** | **C** — код читается, методические источники и область применения неизвестны. |
| **Риск переноса** | **Критический**: использовать только как список факторов до внешней проверки. |

### 2.3. Движитель, пропульсивный КПД и мощность

| Поле | Описание |
| --- | --- |
| **Название** | Диаметр винта, коэффициенты взаимодействия, КПД, буксировочная и электрическая мощность |
| **Pascal-файл** | `HODK.PAS` |

| **Формула** | `Nbuks=R_lk·Vs·0.5144/1000`; затем цепочка эмпирических зависимостей. Итог `N_el=Nbuks/Propuls/(1−6.21·10⁻⁵H+4.81·10⁻⁹H²)` и `N_dz=N_el/0.8`. |
| **Единицы измерения** | `Nbuks,N_el,N_dz` предположительно кВт; `diam` — м; остальные преимущественно безразмерны. |

| **Граничные условия** | Не проверяются `Zv=0`, `1−t=0`, `1−W=0`, `1−W_n=0`, `Propuls=0` (только условное присваивание оставляет старое значение), знак глубинного множителя. `Delta` используется как аргумент `ln`. |
| **Современный аналог** | Независимая, верифицированная модель propulsor/power с typed units, domain validation и uncertainty. |
| **Статус проверки** | **C/D** — выражения читаются, но часть семантики и область коэффициентов не восстановлены. |
| **Риск переноса** | **Критический**; не переносить до методической проверки и regression fixtures. |

## 3. `TABL.PAS`: массовый баланс и энергопотребление

### 3.1. Массово-объёмный баланс

| Поле | Описание |
| --- | --- |
| **Название** | Агрегация статей, производные массы и синтактический балласт |
| **Pascal-файл** | `TABL.PAS` |
| **Процедура или функция** | Вложенная `RaschBalans` в `IO_Balans` (строки 60–132) |
| **Входные данные** | Матрица `bal_a[1..10,1..12]`, масса проекта, коэффициенты `Izm`, геометрия лёгкого корпуса, энергия, `ro_sin`, `rov` |
| **Выходные данные** | Суммы `m0,V0`, расчётные статьи 4–12, `m1,V1`, доли `a,b`, коэффициенты уравнений `n10,n20,…` |
| **Формула** | Примеры: `m_LK=ρ_LK·t_LK·OmegaLK`; `m_DRK=q_DRK·Mosh`; `m_акб=E/(k_o·qak)`; `m_комм=M^(2/3)q_kik`; масса синтактика получена из разности массы и `ρводы·V` делением на разность плотностей. |
| **Единицы измерения** | Масса — кг, объём — л, плотность — кг/л согласно UI (`IO_Balans`, заголовки); энергия/удельные коэффициенты требуют уточнения. |
| **Константы и коэффициенты** | Степени `2/3`, `0.55`; 8 вводимых строк на 12 групп; `Step_ob` выбирает вклад в уравнение объёма. |
| **Граничные условия** | Ветвь синтактика может делить на ноль при равных плотностях; условие выбирается по `m0>V0`, хотя сравниваются разные размерности, если `ρводы≠1 кг/л`; пересчёт `V=m/ρ` происходит после части суммирования. |
| **Современный аналог** | Typed mass budget и buoyancy budget с единицами SI, явным балластом и iterative/solver layer при необходимости. |
| **Статус проверки** | **B** для агрегирования; **C/D** для проектных зависимостей и балластной ветви. |
| **Риск переноса** | **Высокий**: порядок мутаций и смешение размерностей нужно устранить, а не воспроизводить. |

### 3.2. Энергетическая нагрузка

| Поле | Описание |
| --- | --- |
| **Название** | Энергия потребителей и масштабирование мощности ходовых двигателей по прототипу |

## Межмодульные расчётные связи

```text
BOXS (коэффициенты/геометрические предположения)
  ├─> TABL (массовый и энергетический баланс)
  │     ├─> UDIFFER (раскладка отдельных тел)
  │     └─> STOIMOST (Bal.M1 и стоимость аппарата)
  ├─> APPAUNIT (обводы)
  │     └─> ESOBRASP (проекции оборудования)
  └─> HODK (геометрия + скорость → сопротивление → мощность)
        ├─> TABL (мощность ходового двигателя / энергия)
        └─> STOIMOST (N_el в первом приближении стоимости)
```

Связи циклические на уровне mutable state: оценка мощности влияет на массу/энергию, масса влияет на геометрию и стоимость, а стоимость использует результаты баланса. Современная реализация должна разорвать этот цикл на явно упорядоченные pure calculations либо на solver с критерием сходимости.

## Приоритет использования

| Кандидат | Рекомендация | Причина |
| --- | --- | --- |
| `UDIFFER` — взвешенные центры | Перенести как самостоятельную чистую реализацию после coordinate mapping | Формула прозрачна и частично уже соответствует `balance`. |
| `UDIFFER` — тензор инерции | Реализовать заново по стандартной математике | Нужны orientation, products of inertia и полная матрица; исторический код — regression reference, не спецификация API. |
| `APPAUNIT` — обводы/сечения | Использовать как reference и сравнить с текущим `geometry` | Возможна полезная регрессия ЦВК, но нормировки различаются. |
| `TABL` — energy budget | Перенести структуру расчёта `ΣPnt`, не legacy coefficients | Формула энергии стандартна; propulsion source должен быть независим. |
| `BOXS`, `HODK` | Проверить по внешним источникам | Эмпирические зависимости не имеют provenance. |
| `ESOBRASP` | Оставить как исторический UX/rendering reference | Современные adapters и constraints уже архитектурно сильнее. |
| `STOIMOST` | Не переносить коэффициенты; при необходимости создать новую модель | Денежная база и актуальность отсутствуют. |

## Вывод

Первый безопасный implementation slice — не буквальный порт `UDIFFER.PAS`, а независимые pure-функции: взвешенные центры, собственные тензоры простых тел, rotation/parallel-axis transform и суммирование полного тензора в Body/SNAME-NED. Исторический код может служить только источником тестовых гипотез. `HODK`, статистические зависимости `BOXS` и все денежные коэффициенты `STOIMOST` должны оставаться заблокированными до внешней методической проверки.
