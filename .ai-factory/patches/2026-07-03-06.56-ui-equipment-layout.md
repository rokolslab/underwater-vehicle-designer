# Исправление компоновки панели оборудования и ввода наименования

**Date:** 2026-07-03 06:56
**Files:** index.html, src/app/main.ts, src/app/styles.css, src/modules/equipment/placement.ts, src/modules/equipment/placement.test.ts
**Severity:** medium

## Problem

Чекбоксы сетки и точек обвода находились в области размерений, хотя управляют боковым видом. В строке оборудования кнопка удаления могла визуально пересекаться с полем статуса компоновки. В поле `Наименование` нельзя было ввести имя из двух слов, потому что пробел после первого слова сразу удалялся.

## Root Cause

Чекбоксы были привязаны к исходной форме размерений и не были перенесены при предыдущей перестройке UI. Статус оборудования размещался через авто-позиционирование CSS grid, поэтому у форм с разным набором видимых размерных полей он мог попадать не в последнюю статусную колонку. Имя оборудования нормализовалось через `trim()` при каждом `input`, что уничтожало промежуточный хвостовой пробел до ввода второго слова.

## Solution

Чекбоксы `show-grid` и `show-points` перенесены в заголовок панели `Боковой вид`, а клики по ним изолированы от `summary`, чтобы панель не сворачивалась. Для `.equipment-status` и `.equipment-delete` заданы фиксированные последние grid-колонки. `normalizeName` теперь использует `trim()` только для проверки полностью пустого значения, но возвращает исходную строку, сохраняя пробелы при редактировании. Добавлен регрессионный тест на сохранение пробела в имени.

## Prevention

- При переносе контролов в `summary` проверять всплытие кликов у вложенных кнопок, label и input.
- Для строк с условно скрытыми grid-элементами закреплять служебные колонки явно через `grid-column`.
- Не применять destructive normalization к текстовому вводу на каждом keystroke; trim использовать только на commit или для blank-check.
