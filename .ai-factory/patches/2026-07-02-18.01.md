# Локальные clipping planes для 3D-сечения корпуса

**Дата:** 2026-07-02 18:01
**Файлы:** src/modules/rendering/scene3d.ts, src/modules/rendering/scene3d.test.ts
**Серьезность:** medium

## Проблема

В 3D-режиме X-Ray/Cutaway сечение корпуса было задано как `material.clippingPlanes` в world space. После включения среза пользователь мог вращать уже усеченный корпус, но clipping plane оставалась неподвижной относительно мировой/экранной системы координат и начинала пересекать hull mesh под новым углом.

## Причина

`clippingPlanesForSection()` создавала `THREE.Plane` по локальным осям корпуса, но эти planes напрямую назначались в `bodyMaterial.clippingPlanes` и `wireMaterial.clippingPlanes`. В Three.js material clipping planes не наследуют transform mesh/group автоматически: `renderer.localClippingEnabled` включает material-level clipping, но не привязывает plane к `currentHull.rotation`.

## Решение

Локальные planes теперь хранятся отдельно от world-space planes материала. При применении настроек, замене hull mesh и каждом drag-повороте сцена вызывает преобразование local planes через `currentHull.matrixWorld`, после чего обновляет planes, назначенные `bodyMaterial` и `wireMaterial`. Добавлен `[FIX]` debug-log для диагностики трансформации сечения.

Добавлена Vitest-регрессия для `scene3d.ts`: тест проверяет локальные X/XY/XZ planes, преобразование normal через hull matrix и сохранение нулевого расстояния для точки, лежащей на локальной плоскости после того же world transform.

## Профилактика

- Для Three.js clipping явно фиксировать, в какой системе координат живет plane: local domain state отдельно, world material adapter отдельно.
- При изменении transform объекта, к которому логически привязано сечение, пересчитывать world-space adapter state перед render.
- Для визуальных Three.js багов по возможности добавлять чистые unit-тесты на матрицы/геометрию, а не только ручной smoke через canvas/WebGL.
