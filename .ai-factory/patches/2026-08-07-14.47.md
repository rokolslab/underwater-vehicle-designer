# CSV export использует запятую как десятичный разделитель

**Date:** 2026-08-07 14:47
**Files:** src/modules/persistence/csv.ts, src/modules/persistence/csv.test.ts, tests/e2e/import-export.spec.ts, docs/data-and-export.md
**Severity:** low

## Problem

При экспорте CSV координаты станций выгружались с десятичным разделителем `.` (например `0.5`), а требовался десятичный разделитель `,` (например `0,5`). Разделитель полей `;` остаётся без изменений.

## Root Cause

`buildCsv()` собирал строки через `row.join(";")`, где числа преобразовывались стандартным `String(value)` — то есть с точкой для дробных значений. Отдельный formatter для десятичного разделителя отсутствовал.

## Solution

Добавлена чистая функция `formatCsvValue(value)` в `src/modules/persistence/csv.ts`, которая для чисел заменяет `.` на `,` и оставляет строки (заголовок) без изменений. Строки собираются как `row.map(formatCsvValue).join(";")`.

При этом:
- целые значения не меняются (`1;0;3;0;0;0`);
- дробные значения получают запятую (`1;0;0,5;0,8;-0,1;0,1`);
- разделитель полей `;` сохранён — CSV остаётся совместимым с Excel в русской локали;
- `formatNumber` не используется, потому что он форсирует фиксированное число знаков (`0,500`), а текущий экспорт сохраняет точные значения.

## Prevention

- В тестах на export всегда фиксировать конкретную строку результата, чтобы decimal separator был виден явно (`0,5`, а не `0.5`).
- Добавлен regression test «uses comma as decimal separator», который проверяет наличие дробных строк с запятой и отсутствие `.\d` в экспорте.
- E2E проверяет regex `;\d+,\d+` в реальном скачанном CSV.
