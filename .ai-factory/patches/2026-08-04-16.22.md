# Zero-length normals on degenerate hull mesh rings

**Date:** 2026-08-04 16:22
**Files:** `src/modules/rendering/mesh.ts`, `src/modules/rendering/mesh.test.ts`
**Severity:** medium

## Problem

After the `SectionShape` seam migration, bow and stern rings with zero section extents emitted zero-length normals in `buildHullMeshData()`. This could degrade Three.js lighting/shading on degenerate hull rings.

## Root Cause

The mesh builder switched from angle-based ellipse math to `sampleSectionContour()` plus `sectionNormalAtPoint()`. For a zero section, every contour point is `{ y: 0, z: 0 }`, so `sectionNormalAtPoint()` correctly returns `{ y: 0, z: 0 }` because the shape has no geometric normal. The mesh adapter still needs a rendering fallback normal for degenerate rings, but that adapter-specific fallback was not preserved during the migration.

## Solution

Added `contourNormalOrRadialFallback()` in `src/modules/rendering/mesh.ts`. The helper keeps shape-derived normals when they are non-zero and falls back to the radial unit vector from `radialIndex / radialSegments` only for degenerate zero-normal cases. Added a regression test that verifies unit-length normals on degenerate nose and stern rings.

## Prevention

- When moving geometry formulas into pure shape helpers, preserve adapter-specific fallbacks that are not domain geometry, especially rendering normals and degenerate mesh behavior.
- Review mesh migrations for both positions and normals; position regressions alone do not cover lighting behavior.
- Keep regression coverage for zero-section bow/stern rings in mesh tests.
