# Canvas2D base + interaction overlay split (code review blockers)

**Date:** 2026-08-07 12:48
**Files:** src/modules/rendering/canvas2d.ts, src/modules/rendering/canvas2d.test.ts, tests/e2e/import-export.spec.ts, src/app/main.ts, src/modules/rendering/scene3d.ts, index.html, src/app/styles.css
**Severity:** critical

## Problem

5 code review blockers in Canvas2D interaction rendering:

1. **No base/overlay split**: `renderCanvasInteractionOverlay()` called `drawCanvasProfileContent()` which performed a full repaint (clearRect, background, grid, axes, hull, equipment, station labels). Interaction path should not redraw base/project layers.

2. **Non-proving unit tests**: Interaction overlay test only checked `canvas.width`/`canvas.height` didn't change — did not prove that base content wasn't redrawn, that grid/hull/equipment drawing wasn't called, or that only overlay was modified.

3. **Non-deterministic E2E canvas selection**: `selectedCount >= 0` assertion passes even when nothing is selected.

4. **Conditional E2E diagnostics navigation**: `if (diagEntry.count() > 0)` silently passes without verifying actual diagnostics behavior.

5. **Insufficient E2E camera zoom test**: Only checked canvas visibility, not actual camera state.

6. **Insufficient E2E no-DOM-rebuild test**: Row count doesn't prove DOM nodes are preserved.

## Root Cause

`renderCanvasInteractionOverlay()` was a thin wrapper around `drawCanvasProfileContent()` — there was no actual separation between base rendering and interaction rendering. The interaction path triggered a full profile repaint including resize, clearRect, background fill, grid, axes, hull shape, equipment base, station labels, and axis labels.

The same single `<canvas id="profile-canvas">` was used for both base content and interaction highlights. Without a separate overlay canvas, it was impossible to update selection/hover without redrawing base content.

## Solution

### canvas2d.ts

1. Extracted `drawInteractionHighlights()` as a standalone function that ONLY draws selection/hover rects/ellipses on a canvas using a given `CanvasScale`.

2. Removed interaction parameter and interaction drawing code from `drawCanvasProfileContent()`. It now only draws: background, grid, axes, hull shape, equipment base, station points, labels.

3. `renderCanvasProfile()` signature simplified — no longer accepts interaction. Calls `resizeCanvas()` + `drawCanvasProfileContent()`.

4. `renderCanvasInteractionOverlay()` rewritten to accept `overlayCanvas` + `baseCanvas`. Creates scale from base canvas (same transform), calls `drawInteractionHighlights()` only. No resize.

5. Added `syncOverlayCanvasSize()` — syncs overlay backing store to match base canvas dimensions.

6. Added `clearCanvasOverlay()` — clears overlay with the same ratio/transform.

### HTML/CSS

- Wrapped `#profile-canvas` in a `.profile-canvas-wrapper` div with `position: relative`
- Added `#profile-canvas-overlay` canvas with `position: absolute; top:0; left:0; width:100%; height:100%; pointer-events:none; background:transparent` — same CSS size as base, transparent, click-through

### main.ts

- Added overlay canvas reference (`overlayCanvas`)
- `renderPublication()` (project update): `renderCanvasProfile(canvas, ...)` without interaction → `syncOverlayCanvasSize()` → `renderCanvasInteractionOverlay(overlayCanvas, canvas, ..., interaction)` for sync
- `renderInteractionViews()` (interaction only): `updateEquipmentRowsInteraction()` (in-place DOM) → `renderCanvasInteractionOverlay(overlayCanvas, canvas, ..., interaction)` — NO base repaint, NO resize
- `renderCurrentViewsForSize()` (resize handler): resizes both canvases + redraws base + syncs overlay

### scene3d.ts

- Added `HullScene3dCameraState` interface with `position`, `target`, `distance`
- Added `getCameraState()` method to `HullScene3d` — read-only, returns frozen copy of current camera state
- Exposed as `window.__scene3dCameraState` in main.ts for E2E access only

### Unit tests (canvas2d.test.ts)

Added 9 new/spy-based tests that prove the split:

| Test | What it proves |
|---|---|
| `renderCanvasProfile does NOT draw interaction rects on base canvas` | Base canvas stroke colors never include interaction-specific rgba values |
| `renderCanvasInteractionOverlay draws only to overlay, not base canvas` | Overlay gets clearRect + saves/restores; base canvas clearRects/saves/restores remain 0 |
| `interaction-only path does NOT draw grid or hull or labels` | Overlay has 0 fillText, 0 arcs; all strokes match interaction color pattern only |
| `interaction path does NOT call resize on overlay` | Overlay width/height unchanged after interaction render |
| `overlay is cleared and redrawn when selected/hovered state changes` | clearRects=1 on each distinct interaction state transition; clearRects=1 even for null interaction |
| `base and overlay transform produce identical canvas coordinates` | bodyXzToCanvas produces same (x,y) for same (right,down) on both base and overlay scales |
| `clearCanvasOverlay clears the full overlay canvas` | clearRects called, setTransform called with correct ratio |
| `renderCanvasInteractionOverlay uses same scale as base canvas` | Both scales produce identical canvas coordinates for known body point |
| `syncOverlayCanvasSize matches dimensions` | Overlay backing store matches base both at dpr=1 and dpr=2 |

### E2E tests (import-export.spec.ts)

1. **Canvas click selection**: Imports project with known equipment, uses `evaluate()` to determine canvas center, clicks, verifies `[data-equipment-selected]` count = 1 with correct `data-equipment-id="equipment-1"`, verifies inspector shows "Imported box".

2. **Diagnostics navigation**: Places equipment at x=8 (beyond L/2=5) to guarantee diagnostic condition, uses `await expect(diagEntry).toBeVisible()` (NOT conditional `if`), clicks entry, verifies row selected AND focused with correct equipment-id.

3. **3D camera zoom**: Gets camera state via `window.__scene3dCameraState()`, performs wheel zoom, verifies `distance` changed, selects equipment, verifies camera state matches zoomed state exactly (position x/y/z and distance within 1e-8 tolerance).

4. **No-DOM-rebuild hover**: Sets unique marker `__e2e_dom_marker` on first row DOM element via `evaluate()`, hovers second row, reads marker from first row — verifies same DOM node preserved. Additionally verifies row count still 2.

## Prevention

- Any interaction path must only modify overlay canvas, not base canvas
- Tests must verify what functions are NOT called (e.g. fillText, arc, save/restore on base), not just check canvas dimensions
- E2E assertions must fail when behavior is broken — never use `toBeGreaterThanOrEqual(0)` for positive assertions
- Test hooks for E2E must be read-only, not part of public API, and exposed as window properties for evaluate() access
- DOM rebuild tests must use identity markers (custom properties on nodes), not just element count
