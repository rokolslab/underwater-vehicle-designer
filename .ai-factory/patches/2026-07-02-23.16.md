# UI cleanup for underwater vehicle workflow

**Date:** 2026-07-02 23:16
**Files:** index.html, src/app/main.ts, src/app/styles.css, src/modules/equipment/constraints.ts, src/modules/balance/equipment-balance.ts, src/modules/rendering/scene3d.ts, src/modules/ui/metrics.ts, scripts/check-encoding.mjs
**Severity:** medium

## Problem

The UI still used airship wording, exposed station/table details too prominently, showed an unclear x max metric, used oversized input fields, lost focus while editing equipment names, showed English equipment warnings, and allowed the 3D controls to force the 3D panel wider than its parent.

## Root Cause

Several feature increments added engineering data directly to the visible UI without a later usability pass. The equipment editor re-rendered the whole list on every input event, replacing the active input node. The 3D controls used six minimum-width columns that exceeded the available panel width in the default desktop layout.

## Solution

Renamed user-facing hull wording to underwater vehicle terminology, renamed stations to points in the UI, moved coordinates behind a details toggle, removed the x max metric from the visible metrics, compacted control and equipment fields, restored equipment input focus after render, localized equipment/balance warnings, and changed 3D controls/camera framing so the hull opens fully visible.

## Prevention

- Treat any `innerHTML` re-render on `input` as a focus-retention risk during review.
- Check panel min-content widths when adding dense controls to grid layouts.
- Keep engineering internals such as `maxX` out of first-level UI unless the user workflow needs them.
- Run desktop and mobile layout checks after changing Three.js or dense form CSS.
