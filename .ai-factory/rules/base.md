# Базовые правила проекта

> Автоматически выявленные соглашения из текущего кода и технической спецификации. При развитии проекта обновляйте этот файл вручную.

## Именование

- Файлы: текущие файлы используют короткие lowercase-имена (`index.html`, `script.js`, `styles.css`); для будущих TypeScript-модулей используйте `kebab-case`.
- Переменные: `camelCase`.
- Функции: `camelCase`, глагольные имена для действий (`makeStationPoints`, `drawProfile`, `buildCsv`).
- Классы и типы: `PascalCase` для будущих TypeScript типов, классов и интерфейсов.
- Константы: локальные объекты настроек допускаются в `camelCase`; глобальные физические константы в будущих модулях можно оформлять как `UPPER_SNAKE_CASE`.

## Структура модулей

- Текущая версия плоская: `index.html`, `styles.css`, `script.js`.
- При переходе на Vite + TypeScript разделяйте код на вертикальные модули:
  - `geometry` — формулы корпуса, станции, сечения, ЦВК/цилиндрическая вставка.
  - `equipment` — модели оборудования, ограничения размещения, пересечения.
  - `balance` — ЦТ, ЦВ/центр величины, плавучесть, крен и дифферент; не размещайте здесь геометрию ЦВК.
  - `rendering` — 2D canvas/SVG и Three.js-сцена.
  - `persistence` — импорт/экспорт JSON, CSV, SVG.
  - `ui` — состояние интерфейса и связывание DOM/компонентов.

## Обработка ошибок

- Пользовательский числовой ввод нормализуйте через явные функции валидации и fallback-значения.
- Расчетные функции не должны напрямую читать DOM или изменять UI.
- Для невозможной геометрии возвращайте структурированный результат с причиной ошибки, а не скрыто исправляйте состояние.
- Ограничения размещения оборудования должны быть проверяемыми отдельно от визуального слоя.

## Логирование

- В текущем коде логирование отсутствует.
- Для браузерной версии используйте `console.warn` только для диагностируемых некритичных состояний в development-режиме.
- Расчетные ошибки показывайте через UI-состояние, а не только через консоль.

## Тестирование

- Для будущего TypeScript-стека используйте Vitest.
- В первую очередь покрывайте чистые расчетные модули: формула радиуса, станции, объемы, ЦТ/ЦВ, ограничения размещения.
- Для UI и 3D-представления добавляйте smoke-тесты и визуальные проверки только после стабилизации структуры проекта.
