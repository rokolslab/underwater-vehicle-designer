# Архитектурные ограничения

Соблюдай существующие границы проекта:

* расчётные функции должны оставаться чистыми;
* расчёты не читают DOM;
* геометрия корпуса остаётся в `geometry`;
* массы, плавучесть и устойчивость находятся в `balance`;
* оборудование находится в `equipment`;
* рендеринг не должен владеть бизнес-логикой;
* старые Pascal-имена не должны автоматически становиться публичным TypeScript API;
* современная система координат Body/SNAME-NED является основной;
* преобразование исторических координат должно быть явным и документированным.

```bash

```

Проверки нужны, чтобы убедиться, что документальные изменения не нарушили проект.

Review должен проверить:

* архивный репозиторий не изменён;
* production-код не изменён;
* все 31 Pascal-файл учтены;
* выводы имеют ссылки на конкретные файлы и процедуры;
* предположения явно помечены;
* формулы разделены по уровню достоверности;
* roadmap соответствует архитектуре проекта;
* первым implementation-кандидатом выбран `UDIFFER.PAS`;
* нет прямого копирования Pascal-кода в TypeScript;
* нет утверждений о подтверждённой инженерной валидности без доказательств.
