# Описание проекта

## Обзор

Airship — клиентский веб-инструмент для построения и анализа обводов корпуса дирижабля или подводного аппарата по расчетной формуле радиуса. Текущая версия работает как Vite + TypeScript приложение с canvas-визуализацией, Three.js-просмотром, таблицей координат станций, модульной расчетной геометрией, вводом ЦВК/цилиндрической вставки корпуса, базовой моделью оборудования, X-Ray/Cutaway режимами и экспортом SVG/CSV.

В репозитории также есть `TECHNICAL_SPEC.md`, который задает следующий этап: развить модульную структуру до `Three.js`, добавить 3D-представление корпуса, цилиндрическую вставку, размещение оборудования внутри корпуса и расчет ЦТ/ЦВ/крена/дифферента.

## Термины проекта

- `ЦВК` — цилиндрическая вставка корпуса, длина прямого участка постоянного максимального сечения.
- `ЦВ` — центр величины в расчетах баланса; не использовать как сокращение для цилиндрической вставки.
## Текущий стек

- **Язык:** TypeScript
- **Разметка и стили:** HTML, CSS через Vite entrypoint
- **Графика:** Canvas 2D, Three.js
- **Хранение данных:** локальное состояние в памяти браузера
- **Сборка:** Vite
- **Тесты:** Vitest для расчетных модулей, export и UI/appState-регрессии
- **Docker:** multi-stage dev/build/production image и Compose overlays для разработки и VPS smoke checks

## Целевой стек из спецификации

- **Язык:** TypeScript
- **Сборка:** Vite
- **3D-графика:** Three.js
- **Тесты:** Vitest для расчетных модулей
- **Формат сохранения:** JSON для параметров корпуса и оборудования
- **Экспорт:** CSV для координат и расчетов, SVG для 2D-чертежей

## Основные функции

- Расчет радиуса корпуса по формуле `r(x) = 0.972 * D * sqrt((x/L) * (1 - x/L) * (1 - 0.5*x/L))`.
- Связь параметров `D = L / lambda`.
- Построение верхнего и нижнего обвода корпуса.
- Генерация станций, таблицы координат и метрик максимального радиуса.
- Устаревший аналитический расчет вытесненного объема и ЦВ геометрического корпуса как тела вращения; он не является реализацией ЦВК и должен быть отделен от текущего 2D-конструктора.
- Экспорт текущего профиля в SVG и координат в CSV.
- 3D-корпус как тело вращения на Three.js с режимами `solid`, `x-ray`, `cutaway`, регулируемой прозрачностью и clipping-сечениями.
- Базовая модель оборудования: шар, цилиндр и box с массой, координатами, размерами, ориентацией по главным осям, расчетом геометрического объема и центра.
- Планируемые функции: проверки выхода оборудования за корпус, пересечения объектов, JSON import/export и расчет баланса.

## Выявленные паттерны

- Имена переменных и функций в TypeScript используют `camelCase`; типы и интерфейсы используют `PascalCase`.
- DOM-элементы собираются в typed UI/appState слое; расчетные функции отделены от DOM, canvas и export.
- Ошибки пользовательского ввода обрабатываются через `clampNumber` и безопасные fallback-значения.
- Локализация интерфейса ориентирована на русский язык; source files валидны как UTF-8, но Windows/PowerShell display может показывать ложный mojibake без явного UTF-8 чтения.
- Текущий код разделен на `src/app`, `src/modules/geometry`, `src/modules/equipment`, `src/modules/balance`, `src/modules/rendering`, `src/modules/persistence`, `src/modules/ui` и `src/shared`; npm scripts зафиксированы в `package.json`.

## Docker development environment

Docker является предпочтительным воспроизводимым окружением для разработки агентом и VPS smoke checks. Проект включает `Dockerfile`, `compose.yml`, `compose.override.yml`, `compose.production.yml`, `.dockerignore` и `docs/docker.md`. Приложение остается frontend-only Vite + TypeScript SPA; база данных, cache, queue или backend-сервис не добавлялись.

## Нефункциональные требования

- **Точность расчетов:** расчетные функции должны быть чистыми и покрываться регрессионными тестами по `formula.xlsx`.
- **Визуальная проверяемость:** 2D/3D-представления должны соответствовать расчетной геометрии.
- **Производительность:** интерактивное изменение параметров не должно блокировать UI на типовых размерах модели.
- **Локализация:** пользовательский интерфейс и проектные артефакты ведутся на русском языке, технические термины сохраняются в исходном виде, где это уместно.
- **Экспорт и воспроизводимость:** сохранение проекта в JSON должно позволять восстановить параметры корпуса, список оборудования и расчетные настройки.
