# Описание проекта

## Обзор

Airship — клиентский веб-инструмент для построения и анализа обводов корпуса дирижабля или подводного аппарата по расчетной формуле радиуса. Текущая версия работает как статическая HTML/CSS/JavaScript-страница с canvas-визуализацией, таблицей координат станций и экспортом SVG/CSV.

В репозитории также есть `TECHNICAL_SPEC.md`, который задает следующий этап: перейти к модульной структуре на `Vite + TypeScript + Three.js`, добавить 2D/3D-представления корпуса, цилиндрическую вставку, размещение оборудования внутри корпуса и расчет ЦТ/ЦВ/крена/дифферента.

## Текущий стек

- **Язык:** JavaScript в браузере
- **Разметка и стили:** HTML, CSS
- **Графика:** Canvas 2D
- **Хранение данных:** локальное состояние в памяти браузера
- **Сборка:** отсутствует, файлы открываются напрямую
- **Тесты:** отсутствуют

## Целевой стек из спецификации

- **Язык:** TypeScript
- **Сборка:** Vite
- **3D-графика:** Three.js
- **Тесты:** Vitest для расчетных модулей
- **Формат сохранения:** JSON для параметров корпуса и оборудования
- **Экспорт:** CSV для координат и расчетов, SVG для 2D-чертежей

## Основные функции

- Расчет радиуса корпуса по формуле `r(x) = 0.972 * D * sqrt((x/L) * (1 - x/L) * (1 - 0.5*x/L))`.
- Связь параметров `D = L / lambda`.
- Построение верхнего и нижнего обвода корпуса.
- Генерация станций, таблицы координат и метрик максимального радиуса.
- Экспорт текущего профиля в SVG и координат в CSV.
- Планируемые функции: 3D-корпус как тело вращения, цилиндрическая вставка, оборудование внутри корпуса, проверки пересечений и расчет баланса.

## Выявленные паттерны

- Имена переменных и функций в JavaScript используют `camelCase`.
- DOM-элементы собираются в объект `inputs`, расчетные функции отделены от функций отрисовки.
- Ошибки пользовательского ввода обрабатываются через `clampNumber` и безопасные fallback-значения.
- Локализация интерфейса ориентирована на русский язык; source files валидны как UTF-8, но Windows/PowerShell display может показывать ложный mojibake без явного UTF-8 чтения.
- В текущем коде нет модулей, тестов и пакетного менеджера.

## Нефункциональные требования

- **Точность расчетов:** расчетные функции должны быть чистыми и покрываться регрессионными тестами по `formula.xlsx`.
- **Визуальная проверяемость:** 2D/3D-представления должны соответствовать расчетной геометрии.
- **Производительность:** интерактивное изменение параметров не должно блокировать UI на типовых размерах модели.
- **Локализация:** пользовательский интерфейс и проектные артефакты ведутся на русском языке, технические термины сохраняются в исходном виде, где это уместно.
- **Экспорт и воспроизводимость:** сохранение проекта в JSON должно позволять восстановить параметры корпуса, список оборудования и расчетные настройки.
